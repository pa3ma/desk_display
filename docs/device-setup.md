# 実機セットアップと確認の手順

対象: Fire HD 8（第12世代・2022年）、Fire OS 8.3.3.8。
各章の最後に「合格の目安」があります。うまくいかなかった箇所は、画面の表示をそのまま控えておくと原因を追いやすくなります。

---

## 1. 軽量化（実施済みの記録）

Fire OS 8.3.3.8 では、システム権限を使う方法（標準ホームの完全な無効化、ロック画面広告の停止、自動更新の停止）は使えません。使えるのは次の2つです。

| 作業 | 方法 | 状態 |
|---|---|---|
| 不要アプリの停止 | Fire Toolbox → Manage Amazon Apps（自動の推奨設定） | 実施済み |
| ホームの差し替え | Fire Toolbox → Custom Launcher → Launcher Hijack 方式 → Nova Launcher | 実施済み（最初からやり直して成功） |

- タブレット側: 設定 → ユーザー補助 → 一番下の「サービス」で **To detect home button press** をオン。
- ホームを押して「アプリを使用できません…シェルによって管理されています」と出る場合は、Launcher Hijack が効いていません。DialogDismiss をアンインストール → 再起動 → Custom Launcher を再実行、の順でやり直します。
- 「Restore Fire Launcher」は使わない（復元後にホームが空になった報告があるため）。

**記録欄**（更新で設定が戻ったときのために残す）

- Fire Toolbox のバージョン: ＿＿＿＿
- サービス欄でオンにした項目: ＿＿＿＿
- 追加で止めたアプリ: ＿＿＿＿

**合格の目安**: 再起動後もホームボタンで Nova が開く。ブラウザを3時間つけたままにしても固まらない。

**設定が戻ったとき**: 自動更新は止められないため、更新後に上の2つの作業をやり直します。

## 2. カレンダー中継のデプロイ

予定は、自分の Google アカウントで動く小さなスクリプトが取り出して渡します。渡すのは「今から48時間以内」の予定の題名・開始・終了・終日かどうかだけです。

1. PCで <https://script.google.com> を開き、新しいプロジェクトを作る。
2. `relay/Code.gs` の内容をすべて貼り付けて保存する。
3. 左の歯車「プロジェクトの設定」→「スクリプト プロパティ」→ プロパティ名 `TOKEN`、値に **32文字以上の推測できない文字列** を入れる（パスワード生成ツールで作る）。32文字未満だと中継は動きません。
4. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
5. 初回はカレンダーへのアクセス許可を求められるので、内容を確認して許可する。
6. 表示されたウェブアプリのURL（`https://script.google.com/macros/s/…/exec`）の末尾に `?token=（TOKENの値）` を付けたものが **中継URL** です。

**合格の目安**

- PCのブラウザで中継URLを開くと、`[{"id":…,"title":…}]` の形で予定が出る（予定がなければ `[]`）。
- トークンを1文字変えて開くと `{"error":"unauthorized"}` になる。

**注意**

- 中継URLを知っている人は、予定の題名と時刻を読めます。画面共有やスクリーンショットに写さないでください。
- 漏れたと思ったら `TOKEN` の値を変えます。古いURLはすぐ使えなくなります。
- スクリプトを書き換えたときは「デプロイを管理」から新しいバージョンにします（URLは変わりません）。

## 3. Webアプリの公開

アプリ本体に秘密情報は入っていないので、GitHub Pages で公開できます。

1. GitHub に新しいリポジトリを作り、このフォルダの内容を push する。
2. リポジトリの Settings → Pages → Branch を選んで保存する。
3. 数分後に表示される公開URL（`https://＜ユーザー名＞.github.io/＜リポジトリ名＞/`）をPCのブラウザで開く。
4. 右上の「設定」で、緯度・経度と中継URLを入れて「保存する」。

**合格の目安**

- 天気（現在の気温、6時間、明日）が出る。
- 予定が出る（48時間以内に予定がなければ「このあと48時間の予定はありません」）。

**ここで確かめること（未検証の点）**
ブラウザのアプリから中継を読めるかは、この手順で初めて確かめます。予定の欄が「予定を取得できません」のままで、手順2の合格の目安は満たしている場合、ブラウザの制限で読めていない可能性があります。その場合も時計・天気・タイマーは動きます。ブラウザの開発者ツール（F12）の Console に出ている赤い行を控えて、対処を相談してください。

**赤い行を人に見せる前に**: その行には中継URLが `?token=…` まで含まれていることがあります。`token=` より後ろを必ず消してから共有してください。消さずに共有してしまった場合は、手順2の `TOKEN` を新しい値に変えてください。

公開URLは誰でも開けますが、開いた人に見えるのは空のアプリだけです（設定はそれぞれの端末の中に保存されるため）。

## 4. キオスク表示（タブレットで全画面に出す）

全画面で表示し続けるアプリを1つ入れます。次の4つを満たすものを選びます。

| 要件 | 理由 |
|---|---|
| (a) 指定したURLを全画面で開ける | 専用端末として見せるため |
| (b) 端末の起動時に自動で開ける | 再起動や更新のあとに手で開かなくて済むように |
| (c) 画面を消さない設定がある | 常時表示のため |
| (d) 音の自動再生を許可できる | 通知音を鳴らすため（できない場合は、起動後に画面を1回タップすれば鳴ります） |

OSSのキオスクブラウザを先に試し、4つを満たせなければ Fully Kiosk Browser（OSSではありません）を使います。どのアプリがこの端末で要件を満たすかは、こちらでは確認できていません。

設定したら、アプリ内の「設定」から手順3と同じ緯度・経度・中継URLを入力します（設定はブラウザごとに別々に保存されます）。

**記録欄**

- 使ったアプリと版: ＿＿＿＿
- 開始URL: ＿＿＿＿
- 変更した設定項目: ＿＿＿＿

**合格の目安**: タブレットを再起動すると、操作なしでダッシュボードが全画面で出る。

## 5. 電源

- 常時つなぎっぱなしにすると、バッテリーが劣化・膨張しやすくなります。背面が膨らんできたら使用をやめてください。
- この端末（root化なし）では充電の上限を設定できません。対策は次のどちらかです。
  - タイマー付きのコンセントやスマートプラグで、1日数時間だけ充電する。
  - つなぎっぱなしで使い、ときどき背面の膨らみを確かめる。
- 直射日光の当たる場所や、熱のこもる場所には置かないでください。

**記録欄**: 採用した方式 ＿＿＿＿

## 6. 実機確認チェックリスト

項目3と4は、確認を早く済ませるため、設定で「作業（分）」を **1** にして行います。終わったら 25 に戻し、項目5以降は 25 のまま行います。

| # | 確認すること | 合格の目安 | 結果 |
|---|---|---|---|
| 1 | 起動時の自動表示 | 再起動後、操作なしでダッシュボードが出る | |
| 2 | 通知音の有効化 | 下端の「タップして通知音を有効にする」を押すと短い音が鳴り、帯が消える。消えない場合は、もう一度押す（音が出せる状態になるまで帯は残ります） | |
| 3 | 作業の終了 | 1分後に音が鳴り、画面が数回明滅して緑（休憩）に変わる。丸が1つ埋まる | |
| 4 | 一時停止・リセット・スキップ | それぞれ表示どおりに動く | |
| 5 | 再起動後の復元 | 作業25分のタイマーを開始してからタブレットを再起動すると、残り時間が続きから出る（再起動にかかった分だけ減っている） | |
| 6 | 予定の通知 | 45分後に始まる予定を作る → 30分以内に画面に出る → 開始10分前に音と帯で知らせる。5分以上触っていなくても、通知のときは画面が明るくなる | |
| 7 | Wi-Fi 切断 | Wi-Fiを切ってもタイマーと時計が動く。30分後、天気に「（更新できません）」と前回の更新時刻が出る。Wi-Fiを戻すと、数分以内に更新される | |
| 8 | 減光 | タイマー停止中に5分触らないと暗くなり、タッチで戻る。タイマー作動中は暗くならない | |
| 9 | 縦置き | 縦にしても文字が重ならない | |
| 10 | 連続表示 | 24時間つけたままで固まらない。時刻がずれない | |

予定の反映は最大30分かかります（30分ごとに取得するため）。急ぐときは、キオスクアプリでページを再読み込みすると、すぐに取得し直します。取得に失敗したときは、1分後から間隔をあけながら自動でやり直します。
