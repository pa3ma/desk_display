# 実機セットアップと確認の手順

対象: Fire HD 8（第12世代・2022年）、Fire OS 8.3.3.8。
各章の最後に「合格の目安」があります。うまくいかなかった箇所は、画面の表示をそのまま控えておくと原因を追いやすくなります。

---

## 1. 軽量化（実施済みの記録）

Fire OS 8.3.3.8 では、システム権限を使う方法（標準ホームの完全な無効化、ロック画面広告の停止、自動更新の停止）は使えません。使えるのは次の2つです。

| 作業 | 方法 | 状態 |
|---|---|---|
| 不要アプリの停止 | Fire Toolbox → Manage Amazon Apps（自動の推奨設定） | 実施済み |
| ホームの差し替え | Fire Toolbox → Custom Launcher → Launcher Hijack 方式 → Nova Launcher | 実施済み（最初からやり直して成功） |

- タブレット側: 設定 → ユーザー補助 → 一番下の「サービス」で **To detect home button press** をオン。
- ホームを押して「アプリを使用できません…シェルによって管理されています」と出る場合は、Launcher Hijack が効いていません。DialogDismiss をアンインストール → 再起動 → Custom Launcher を再実行、の順でやり直します。
- 「Restore Fire Launcher」は使わない（復元後にホームが空になった報告があるため）。

**記録欄**（更新で設定が戻ったときのために残す）

- Fire Toolbox のバージョン: ＿＿＿＿
- サービス欄でオンにした項目: ＿＿＿＿
- 追加で止めたアプリ: ＿＿＿＿

**合格の目安**: 再起動後もホームボタンで Nova が開く。ブラウザを3時間つけたままにしても固まらない。

**設定が戻ったとき**: 自動更新は止められないため、更新後に上の2つの作業をやり直します。

## 2. カレンダー中継のデプロイ

予定は、自分の Google アカウントで動く小さなスクリプトが取り出して渡します。渡すのは「今日から7日間」の予定の題名・開始・終了・終日かどうかだけです。同じスクリプトが、充電用プラグの操作も受け持ちます（6章、使う場合のみ）。

1. PCで <https://script.google.com> を開き、新しいプロジェクトを作る。
2. `relay/Code.gs` の内容をすべて貼り付けて保存する。
3. 左の歯車「プロジェクトの設定」→「スクリプト プロパティ」→ プロパティ名 `TOKEN`、値に **32文字以上の推測できない文字列** を入れる（パスワード生成ツールで作る）。32文字未満だと中継は動きません。
4. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
5. 初回はカレンダーへのアクセス許可を求められるので、内容を確認して許可する。
6. 表示されたウェブアプリのURL（`https://script.google.com/macros/s/…/exec`）の末尾に `?token=（TOKENの値）` を付けたものが **中継URL** です。

**合格の目安**

- PCのブラウザで中継URLを開くと、`[{"id":…,"title":…}]` の形で予定が出る（予定がなければ `[]`）。
- トークンを1文字変えて開くと `{"error":"unauthorized"}` になる。

**注意**

- 中継URLを知っている人は、予定の題名と時刻を読めます。6章の設定をした場合は、充電用プラグも操作できます。画面共有やスクリーンショットに写さないでください。
- 漏れたと思ったら `TOKEN` の値を変えます。古いURLはすぐ使えなくなります。
- スクリプトを書き換えたときは「デプロイを管理」から新しいバージョンにします（URLは変わりません）。

### 2-1. 中継の更新（v2 にしたとき）

v1 の中継を使っている場合は、新しい `relay/Code.gs` に入れ替えます。入れ替えないと、週間画面には48時間分しか出ず、充電の自動制御も動きません（ほかの機能は動きます）。

1. Apps Script のプロジェクトを開き、`Code.gs` の中身を新しい `relay/Code.gs` の内容にすべて置き換えて保存する。
2. 右上「デプロイ」→「デプロイを管理」→ 鉛筆のアイコン → バージョン「新バージョン」→「デプロイ」。
3. URL とトークンは変わりません。タブレット側の設定はそのままで構いません。

**合格の目安**: PCのブラウザで中継URLを開くと、今日から7日分の予定が出る。

## 3. Webアプリの公開

アプリ本体に秘密情報は入っていないので、GitHub Pages で公開できます。

1. GitHub に新しいリポジトリを作り、このフォルダの内容を push する。
2. リポジトリの Settings → Pages → Branch を選んで保存する。
3. 数分後に表示される公開URL（`https://＜ユーザー名＞.github.io/＜リポジトリ名＞/`）をPCのブラウザで開く。
4. 右上の「設定」で、緯度・経度と中継URLを入れて「保存する」。

**合格の目安**

- 天気（現在の気温、6時間、明日）が出る。
- 予定が出る（48時間以内に予定がなければ「このあと48時間の予定はありません」）。

**ここで確かめること（未検証の点）**
ブラウザのアプリから中継を読めるかは、この手順で初めて確かめます。予定の欄が「予定を取得できません」のままで、手順2の合格の目安は満たしている場合、ブラウザの制限で読めていない可能性があります。その場合も時計・天気・タイマーは動きます。ブラウザの開発者ツール（F12）の Console に出ている赤い行を控えて、対処を相談してください。

**赤い行を人に見せる前に**: その行には中継URLが `?token=…` まで含まれていることがあります。`token=` より後ろを必ず消してから共有してください。消さずに共有してしまった場合は、手順2の `TOKEN` を新しい値に変えてください。

公開URLは誰でも開けますが、開いた人に見えるのは空のアプリだけです（設定はそれぞれの端末の中に保存されるため）。

## 4. キオスク表示（タブレットで全画面に出す）

全画面で表示し続けるアプリを1つ入れます。次の4つを満たすものを選びます。

| 要件 | 理由 |
|---|---|
| (a) 指定したURLを全画面で開ける | 専用端末として見せるため |
| (b) 端末の起動時に自動で開ける | 再起動や更新のあとに手で開かなくて済むように |
| (c) 画面を消さない設定がある | 常時表示のため |
| (d) 音の自動再生を許可できる | 通知音を鳴らすため（できない場合は、起動後に画面を1回タップすれば鳴ります） |

OSSのキオスクブラウザを先に試し、4つを満たせなければ Fully Kiosk Browser（OSSではありません）を使います。どのアプリがこの端末で要件を満たすかは、こちらでは確認できていません。

設定したら、アプリ内の「設定」から手順3と同じ緯度・経度・中継URLを入力します（設定はブラウザごとに別々に保存されます）。

**記録欄**

- 使ったアプリと版: ＿＿＿＿
- 開始URL: ＿＿＿＿
- 変更した設定項目: ＿＿＿＿

**合格の目安**: タブレットを再起動すると、操作なしでダッシュボードが全画面で出る。

## 5. 電源

- 常時つなぎっぱなしにすると、バッテリーが劣化・膨張しやすくなります。どの方法でも、月に一度は背面が膨らんでいないか確かめ、膨らんできたら使用をやめてください。
- この端末（root化なし）では、端末側で充電の上限を設定できません。代わりに、**SwitchBot プラグミニで残量に応じて充電を入れたり切ったりできます（次章）**。
- 次章の方法が使えない場合（アプリが電池の残量を読めない端末など）は、次のどちらかにします。
  - タイマー付きのコンセントで、1日数時間だけ充電する。
  - つなぎっぱなしで使い、ときどき背面の膨らみを確かめる。
- 直射日光の当たる場所や、熱のこもる場所には置かないでください。

**記録欄**: 採用した方式 ＿＿＿＿

## 6. 充電の自動制御（SwitchBot プラグミニ）

対象: SwitchBot プラグミニ（JP）W2001400。Wi-Fi（2.4GHz）につながっていて、SwitchBot アプリから操作できる状態にしておきます。

**仕組み**: アプリが電池の残量を見て、35%以下になったらプラグを入れ、80%以上になったら切ります（設定で変更可）。指示は中継スクリプトを通して SwitchBot に送ります。

**電池切れを防ぐしくみ**（迷ったらプラグを入れる側に倒します）

- アプリは10分ごとに中継へ「動いています」と連絡します。連絡が30分途絶えると、中継が自動でプラグを入れます（15分ごとの確認なので、実際には30〜45分後）。
- 電池の値が信用できないときは、アプリが自動制御を止めてプラグを入れ、連絡もやめます。たとえば、切った後に残量が60分変わらない、切る指示を送り直しても充電中のまま、のような場合です。設定画面にその旨が出ます。
- 電池の残量を読めない端末では、自動制御をせず、連絡もしません。中継の安全策がプラグを入れたままにします。

### 6-1. SwitchBot のトークンとシークレットを取る

1. スマホの SwitchBot アプリで、プロフィール → 設定 → 基本データ（または「アプリについて」）を開く。
2. 「アプリバージョン」を10回続けてタップすると「開発者向けオプション」が出る。
3. 開発者向けオプションを開き、**トークン** と **クライアントシークレット** を控える。

メニューの名前と場所は、アプリの版によって少し違います。

### 6-2. 中継に登録する

1. Apps Script のプロジェクト →「プロジェクトの設定」→「スクリプト プロパティ」に次を追加する。
   - `SWITCHBOT_TOKEN`: 控えたトークン
   - `SWITCHBOT_SECRET`: 控えたクライアントシークレット
2. プラグのデバイスIDを調べる: 編集画面の上の関数選択で **listSwitchBotDevices** を選び「実行」。下の実行ログに「名前（種類）: ID」の一覧が出るので、プラグの ID を控える。初回はアクセスの許可を求められます。
3. スクリプト プロパティに `SWITCHBOT_DEVICE_ID`（控えた ID）を追加する。
4. 左の時計のアイコン「トリガー」→「トリガーを追加」
   - 実行する関数: **failSafe**
   - イベントのソース: 時間主導型 / 時間ベースのトリガーのタイプ: 分ベースのタイマー / 間隔: **15分おき**
5. 2-1 の手順で、中継を新しいバージョンとしてデプロイし直す（v1 の中継を使っていた場合）。

**合格の目安**

- PCのブラウザで、中継URLの末尾に `&action=plug&state=off` を付けて開くと、プラグが切れて `{"ok":true,"state":"off"}` が出る。
- `&action=plug&state=on` でプラグが入り、`{"ok":true,"state":"on"}` が出る。
- `{"error":"plug_not_configured"}` が出る場合は、スクリプト プロパティの名前か値が足りていません。`{"error":"plug_failed"}` の場合は、トークン・シークレット・デバイスIDのどれかが違うか、プラグがネットにつながっていません。

### 6-3. タブレットで有効にする

1. アプリの「設定」→「充電の自動制御」で「自動で充電を入れたり切ったりする」にチェックを入れ、「保存する」。
2. 同じ欄に「残量 ◯%」が出ていれば、電池の残量を読めています。**その数字が、タブレット上部のステータスバーの残量と合っているか**確かめます。
3. 充電器を抜いて10〜20分待ち、ホーム右上の残量が減ることを確かめます（値が止まったままの端末では、自動制御が正しく働きません）。
4. 「この端末では電池の残量を読めないため…」と出る場合、自動制御は働きません。プラグは入れたままにし、5章の方法を使ってください（アプリから連絡が来ないため、中継の安全策が30分ほどでプラグを入れます）。

**注意**

- プラグには、タブレットの充電器だけをつないでください。安全策が働くと、プラグは自動で入ります。
- トークンとシークレットは、プラグを操作できる鍵です。人に見せないでください。漏れた場合は SwitchBot アプリでトークンを再発行し、スクリプト プロパティを書き換えます。
- キオスクアプリが止まると、30〜45分後にプラグが入ります。故障ではありません。
- **家の Wi-Fi やネット回線が止まっているときは、安全策も働きません**（プラグがクラウドからの指示を受け取れないため）。停電や回線の工事で長く止まるときは、プラグを手で入れておいてください。プラグ本体のボタンで入切できます。
- 「入れる残量」を低くしすぎると、回線が止まったときの余裕がなくなります。既定の35%から下げないことをおすすめします。
- このアプリを、同じ中継URLで別の端末やブラウザからも開き、自動制御を有効にすると、その端末の電池でプラグが動き、タブレットが止まっても気づけなくなります。自動制御は、このタブレットだけで有効にしてください。

**記録欄**: 入れる残量 ＿＿%／切る残量 ＿＿%
