# Pi Zero 2 W 卓上スマートディスプレイ 設計書（改訂版）

日付: 2026-11-12 / 状態: レビュー待ち / 前版からの変更: Echo Show風のタッチ画面に拡張、音声は将来の拡張点のみ

## 1. 目的
Echo Show のような卓上スマートディスプレイを、OSSと自作コードで作る。ポモドーロタイマーを中心に、時計・天気・室内環境・Googleカレンダーの予定を、タッチ操作のカード型画面で確認できる。

## 2. 機能範囲
含む:
- ポモドーロタイマー（作業25分/休憩5分、4回ごとに長休憩15分。時間は設定可）
- 時計・日付、天気（現在＋数時間〜翌日）、室温・湿度（BME280）
- Googleカレンダーの予定表示（読み取り専用、非公開iCal URL）と予定前通知（既定10分前）
- ブザー/LED通知（作業⇔休憩の切替、予定前）
- タッチ操作（ホーム画面のカード、タイマー画面、タップで切替）

含まない（今回作らない）: 音声操作、作業ログ、Web UI、カレンダーへの書き込み、スマホアプリ。
音声は「将来、外部の音声基盤からイベントを受け取れる入口」だけ用意する（§6）。
スマホ連携は、スマホで登録した予定がGoogle経由で反映されることで実現する。

## 3. ハードウェア方針
- 本体: Raspberry Pi Zero 2 W（512MB, mini HDMI, Wi-Fi内蔵）
- 表示/入力: 5〜7インチのHDMIタッチパネル（HDMI映像＋USBタッチ）。型番は計画段階で確定し、コードは解像度を設定値として扱う。
- 出力: ブザー1個、LED1個。センサー: BME280（I2C）。
- 音声のマイク・スピーカーは今回搭載しない。
- 手持ちの古い Fire HD 8 は、動作が重いため表示端末には使わない（検討済み）。パネル単体の流用も、制御基板の用意が必要で見送る。スピーカーは将来の音声拡張時に再検討する。

## 4. アーキテクチャ（単一Pythonアプリ、systemdで常駐）
描画は Python + pygame(SDL2) で、デスクトップ環境やブラウザを使わず直接描く。
```
core/timer      ポモドーロ状態機械（時計を外から注入）
core/events     イベントバス（タッチ・タイマー・通知・将来の音声が共通の入口）
services/weather    Open-Meteoから30分ごと取得、ファイルにキャッシュ
services/calendar   iCal URLを30分ごと取得し直近の予定を抽出
services/sensor     BME280を読む
hw/display_input, hw/buzzer_led   実機I/O（PC用の偽実装あり）
ui/cards, ui/screens   カード部品と画面（ホーム/タイマー）
app.py          組み立てと主ループ
```
各モジュールは単独で目的・使い方・依存を説明できる単位にする。

## 5. 画面
- ホーム: 時刻・日付、天気、室温湿度、直近の予定をカード表示。
- タイマー: 残り時間（秒単位）、フェーズ、セット数、開始/一時停止/リセットのタッチボタン。
- 画面描画は既定30fps未満に抑え、静止画面では再描画を減らす（上限は実機計測で決める）。
- 長時間表示の焼き付き対策として、一定時間操作がなければ減光する（設定可）。

## 6. 将来の音声拡張点
`core/events` が受け付けるコマンド（例: タイマー開始、天気を表示）を明文化し、外部プロセス（Wyoming Satellite 等）から同じコマンドを送れる口を後付けできる形にする。今回は実装しない。

## 7. データの流れ
タッチ → イベントバス → 状態機械/画面 → 描画・ブザー。天気・カレンダー・センサーは別スレッドで取得し、画面は最新値を読むだけ。

## 8. エラー処理
- 天気/カレンダー取得失敗: 前回値を最終更新時刻つきで表示。タイマーと時計は止めない。
- センサー失敗: 該当カードを「--」表示。
- Wi-Fi断中もタイマーは動く。
- iCal URLは秘密情報。設定ファイル（Git管理外）に置き、ログに出さない。

## 9. 設定
`config.toml`（Git管理外）: 緯度・経度、タイムゾーン（既定 Asia/Tokyo）、iCal URL、画面解像度、各時間設定、通知前倒し分数、減光時間。

## 10. 外部サービス・参考OSS（計画段階で最新仕様を確認する）
- 天気: Open-Meteo（APIキー不要）。カレンダー解析: `icalendar` と繰り返し予定展開ライブラリを候補とする。
- 設計の参考のみでコードは流用しない: InkyPi（GPL-3.0）、View Assist、OVOS、Wyoming Satellite。

## 11. 検証（正しさの示し方）
1. `pytest`（PC上）: 偽の時計で状態機械を検証（25分で休憩へ、4回目で長休憩、一時停止/再開/リセット）。
2. `pytest`: iCalサンプル（繰り返し・終日・タイムゾーン違い）から正しい予定を抽出。天気のレスポンス変換と、失敗時のキャッシュ表示。
3. PC上で各画面をPNG出力して目視確認。
4. **実機での性能確認（最初のスパイク）**: 実機で pygame の最小画面を表示し、メモリ使用量とフレームレートを計測する（`free -m` と fps のログ）。目標値は計測後に決める。実機の操作はユーザーが行う。
5. 実機の手順書で、タッチ、ブザー、センサー値、Wi-Fi断、再起動後の自動起動を確認する。

## 12. 自己レビュー結果
プレースホルダなし。型番は計画段階で確定する旨を明記。音声は拡張点のみで、スコープは1つの実装計画に収まる。512MBでの描画性能は未検証なので、検証項目4で最初に確かめる。
