# 卓上ディスプレイ v2 設計書（バー式タイマー・週間カレンダー・24時間天気・追加機能）

日付: 2026-11-13 / 状態: レビュー待ち
前提: `2026-11-12-fire-hd8-smart-display-design.md`（v1、実装済み・ブランチ `feat/dashboard`）。この文書は v1 からの変更点だけを書く。書いていない点は v1 のまま。

## 1. 変更の目的
v1 はホーム1画面に要約を並べる構成だった。利用者の要望により、(1) タイマーを目盛りバーで視覚的に、(2) 予定を週間カレンダーで、(3) 天気を1時間ごとに1日分、表示する。あわせて定期リマインダー、雨の予告、夜間の自動減光を加える。

## 2. 画面構成（3画面＋設定をタブで切替）
画面下端にタブ（ホーム／週間／天気／設定）。高さ64px以上。v1 の右上の「設定」リンクは廃止。
- 設定以外の画面で2分間操作がなければホームに戻る。
- 画面全体の地色がタイマーの状態を表す点は v1 のまま。

### 2.1 ホーム
- 上段: 左に日付と時刻（v1 より小さく）、右に今の天気（アイコン・気温・天気名）と雨の予告。
- 中段: **バー式タイマー**（§3）。タップするとタイマー画面へ。
- 下段: 次の予定を最大2件（v1 と同じ表示規則）。

### 2.2 週間（週間カレンダー）
- 今日から7日分を7列で表示。列の見出しは「曜日＋日」。今日の列を強調。
- 各列は上から、終日予定、時刻付き予定（開始時刻順、「10:00 題名」）、定期リマインダー（その曜日のもの）。
- 1列に入りきらない分は「ほか n 件」と表示。題名は1行で末尾省略。
- 複数日にまたがる予定は、かかる日すべての列に出す。
- 縦置きでは7行（1日1行）に組み替える。

### 2.3 天気（24時間）
- 現在の天気と、これから24時間を1時間ごとに表示（時刻・アイコン・気温・降水確率）。
- 横置きは12列×2段、縦置きは6列×4段。日付が変わる位置に「明日」の印。
- 降水確率は数字に加えて、セル下部の棒の高さでも示す。

### 2.4 タイマー画面
v1 の操作ボタン（開始／一時停止・リセット・スキップ）はそのまま。残り時間の数字の下にバー式タイマーを置く。

## 3. バー式タイマー
キングジム「ビジュアルバータイマー」の考え方（横方向の目盛りが減っていき、残り時間が一目で分かる）にならう。製品の意匠は写さない。
- 横一列の **20目盛り**。1目盛り＝フェーズの長さの5%。時間の経過とともに右端から消える（残り時間表示）。
- 消えかけの目盛りは、残りの割合に応じて薄くする（1目盛りの中の進みも見える）。
- 残り2目盛り（10%）以下は目盛りを琥珀色にする。
- バーの左にフェーズ名（作業／休憩／長休憩）、右に残り時間の数字。
- 待機中は20目盛りすべて点灯。一時停止中はバー全体を半分の濃さにする。
- 計算は純粋関数 `barSegments(remainingMs, totalMs, count = 20) -> number[]`（各目盛りの濃さ 0〜1）にして単体テストする。

## 4. カレンダー中継の変更
- 取得範囲を「今から48時間」から「**今日の0時（日本時間）から7日間**」に変える。返す項目は v1 と同じ（id・題名・開始・終了・終日）。
- **利用者の作業が必要**: Apps Script に新しい `Code.gs` を貼り直し、「デプロイを管理」から新しいバージョンにする（URLとトークンは変わらない）。
- 古い中継のままでも動く（48時間分だけ表示される）。

## 5. 追加機能
### 5.1 定期リマインダー
- 設定画面で登録・削除する。項目: 題名（1〜30文字）、曜日（複数可）、時刻（HH:MM）。最大20件。端末の `localStorage`（`desk.reminders`）に保存。
- 指定の曜日・時刻になったら、v1 の予定通知と同じ方法（音・明滅・帯60秒）で知らせる。
- 通知できるのは指定時刻から10分以内。端末が止まっていて10分を過ぎた分は鳴らさない。1日1回だけ（再読み込みでも繰り返さない）。
- 週間画面の該当する曜日の列にも表示する。
- 純粋関数 `dueReminders(reminders, nowMs, notified)`、`remindersOn(reminders, dayMs)`、`validateReminder(input)`。

### 5.2 雨の予告
- これから3時間以内に、降水確率50%以上または雨・雪・雷雨の天気コードの時間帯があれば、ホームに「15時ごろから雨（60%）」と表示する。音は鳴らさない。
- 純粋関数 `rainNotice(forecast, nowMs) -> { timeMs, pop, label } | null`。

### 5.3 夜間の自動減光
- 設定: 有効／無効、開始時刻（既定 22:00）、終了時刻（既定 7:00）。既定は有効。
- 夜間は、無操作30秒で減光し、減光を通常（78%）より濃く（92%）する。タッチすれば戻る。
- 夜間でも、タイマー作動中は減光しない。通知のときは明るさを戻す（v1 レビュー修正のまま）。
- 純粋関数 `isNight(nowMs, startHHMM, endHHMM)`（日付をまたぐ範囲に対応）。

### 5.4 電源管理（SwitchBot プラグによる自動充電制御）
利用者の手持ちの SwitchBot プラグを使う。Tapo は公式の公開APIがなく、非公式の方法は自宅内の常時稼働機か、仕様変更で止まりうるクラウド経路が要るため使わない。
- アプリは電池の残量と充電状態を読み（ブラウザの Battery Status API）、ホームの隅に残量を表示する。
- 残量が **35%以下** でプラグを入れ、**80%以上** で切る（設定で変更可、下限20〜50、上限60〜90）。
- プラグの操作はカレンダー中継（Apps Script）経由で行う。SwitchBot のトークン・シークレット・デバイスIDは Apps Script のスクリプトプロパティにだけ置き、アプリにもリポジトリにも置かない。中継は「入れる／切る」の2操作と、指定した1台のデバイスしか受け付けない。
- **安全策（電池切れ防止）**: アプリは操作のたび、および10分ごとに中継へ生存連絡を送る。中継は時間主導トリガーで15分ごとに確認し、**生存連絡が30分途絶えていたらプラグを入れる**。アプリやWi-Fiが止まっても、充電されない状態で放置されない。
- 残量を読めない端末・ブラウザでは自動制御を行わず、その旨を設定画面に表示する。この場合プラグは入れたままにする。
- 純粋関数 `plugDecision({ level, charging, low, high, lastCommand }) -> 'on' | 'off' | null`（同じ指示を繰り返し送らない。境界でばたつかない）。中継側の判定 `shouldFailSafe(lastSeenMs, nowMs)` も単体でテストする。
- 利用者の作業: SwitchBot アプリでトークンとシークレットを取得し、デバイスIDとともにスクリプトプロパティへ登録。時間主導トリガーを1つ追加。手順は `docs/device-setup.md` に書く。
- 未確認: Fire のキオスク表示で残量が読めるか。SwitchBot API の1日あたりの呼び出し上限（操作は1日数回、生存確認は中継内で完結するため、上限に近づかない設計とする）。

## 6. 作らないもの
写真スライドショー、ポモドーロの実績記録、音声操作、室温・湿度（v1 と同じ）、Tapo プラグの制御。

## 7. 検証（正しさの示し方）
1. 単体テスト（`npm test`）: `barSegments`（開始・途中・残り10%・0・一時停止は表示側）、週間の日ごとの振り分け（終日・複数日・日付境界・日本時間）、`rainNotice`、`isNight`（22:00→7:00 をまたぐ、同時刻、無効）、`dueReminders`（曜日・10分の窓・1日1回・再読み込み）、`validateReminder`、`plugDecision`（35%で入、80%で切、境界での繰り返しなし、残量不明）、`shouldFailSafe`。
2. ブラウザの通し確認（`tools/e2e.py`）: タブ切替と2分での自動復帰、バーの目盛り数が時間とともに減る、週間画面に中継の予定と定期リマインダーが出る、定期リマインダーの登録→通知→再読み込みで再通知なし、夜間の減光と通知時の復帰。
3. 画面の画像出力（`tools/screenshot.py`）: ホーム・週間・天気・タイマー・設定を横置きと縦置きで出力し、はみ出しがないこと。
4. 実機: `docs/device-setup.md` のチェックリストに項目を追加（利用者が実施）。中継の再デプロイ手順を追記。

## 8. v1 レビューで先送りした小さな指摘のうち、v2 で一緒に直すもの
- 「明日は…」が日付をまたいだ直後に今日の予報を指す → 24時間表示への置き換えで解消。
- 終日予定が時刻付き予定2件に隠れる → 週間画面で全件見えるため解消。ホームの「次の予定」は v1 のまま。
- 帯が日付と設定リンクを覆う → タブを下端に移すため、設定には常に届く。
