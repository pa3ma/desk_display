# 卓上ディスプレイ v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v1 のダッシュボードに、バー式タイマー、週間カレンダー、24時間の天気、定期リマインダー、雨の予告、夜間の自動減光、SwitchBot プラグミニによる自動充電制御を加える。

**Architecture:** v1 と同じく、判定はすべて DOM に依存しない純粋関数（`src/core/`, `src/services/`）に置き `node --test` で検証する。画面は下端タブで切り替える4画面（ホーム／週間／天気／設定）＋タイマー画面に組み替える。プラグ操作と生存確認は既存のカレンダー中継（`relay/Code.gs`）に操作を足し、SwitchBot の認証情報は中継のスクリプトプロパティにだけ置く。中継は `node:vm` に読み込んで単体テストする。

**Tech Stack:** v1 と同じ（HTML/CSS/ES Modules、依存なし、Node.js 22 `node --test`、Playwright + Chrome、Google Apps Script、Open-Meteo）。追加: Battery Status API、SwitchBot API v1.1。

**Spec:** `docs/superpowers/specs/2026-11-13-display-v2-design.md`（v1 の仕様 `2026-11-12-fire-hd8-smart-display-design.md` を前提とする）

## Global Constraints

- v1 の Global Constraints をすべて引き継ぐ（依存追加なし、1280×800 と 800×1280、日本語、`Asia/Tokyo` 固定、秘密情報を出さない、取得失敗でも時計とタイマーを止めない、`desk.` 接頭辞）。
- 既定値: バーは20目盛り・残り10%以下で琥珀色／自動でホームへ戻るまで2分／雨の予告は3時間以内・降水確率50%以上／夜間は 22:00〜7:00・有効・無操作30秒で減光・濃さ92%／リマインダーは最大20件・題名1〜30文字・通知の窓10分／プラグは35%以下で入・80%以上で切／生存連絡10分ごと／中継の安全策は連絡が30分途絶えたら入。
- 中継の取得範囲は「今日の0時（日本時間）から7日間」。返す項目は v1 と同じ。
- SwitchBot のトークン・シークレット・デバイスIDは、アプリ・リポジトリ・ログ・画面のどこにも置かない。中継は登録済みの1台に対する `turnOn` / `turnOff` だけを送る。
- 対象プラグ: SwitchBot プラグミニ（JP）W2001400。
- 新しい `localStorage` キー: `desk.reminders`, `desk.power`。
- v1 の既存テスト（単体71件、通し確認45項目）を壊さない。画面構成の変更で意味を失う通し確認は、同じ内容を新しい画面で確かめ直す。

## Review Focus

1. 電池の状態を読めない（API がない、権限で拒否、値が返らない）→ 自動制御をせず、プラグは切らない。設定画面にその旨が出る（Task 5, 6）。
2. プラグの指示が失敗した（中継に届かない、中継がエラーを返す、v1 の古い中継が予定の配列を返す）→ 成功として扱わず、次の周期でやり直す。電池が下限以下なら「入」を送り続ける（Task 5）。
3. 定期リマインダーが、再読み込み・スリープ明け・日付変更をまたいでも、1日1回・指定時刻から10分以内にだけ鳴る（Task 3）。
4. 週間表示の日付の境界: 端末のタイムゾーンが日本以外でも日本時間で区切る。0時ちょうどに終わる予定や終日予定が、翌日の列に出ない。複数日の予定は各日に出る（Task 2）。
5. 夜間の減光中でも通知は見える。タイマー作動中は減光しない。夜間の開始と終了が同じ時刻、または日付をまたぐ設定でも正しく判定する（Task 4, 6）。

### Task 2: 週間カレンダーの振り分け

**Files:** Create `src/core/week.js` / Test `tests/week.test.js`

**Interfaces:**
- Consumes: `CalEvent`（v1）
- Produces:
  - `jstDayStart(ms) -> number`（その時刻を含む日本時間の日の0時）
  - `weekDays(nowMs, count = 7) -> Array<{ startMs, endMs }>`（今日から `count` 日。`endMs` は翌日0時）
  - `eventsByDay(events, days) -> Array<{ allDay: CalEvent[], timed: CalEvent[] }>`（`days` と同じ長さ。予定は `startMs < day.endMs && endMs > day.startMs` の日に入る。`timed` は開始時刻順、`allDay` は題名順）

- [ ] **Step 1: 失敗するテストを書く** — 次を assert する:
  - `jstDayStart(Date.parse('2026-11-12T23:59:59+09:00'))` と `jstDayStart(Date.parse('2026-11-12T00:00:00+09:00'))` がともに `Date.parse('2026-11-12T00:00:00+09:00')`。UTC 15:00 ちょうどは翌日。
  - `weekDays` は7件で連続し、各 `endMs - startMs === 86400000`。
  - 10:00〜11:00 の予定は当日の `timed` にだけ入る。
  - 23:00〜24:00（0時ちょうどに終了）の予定は翌日に入らない。
  - 終日予定（0時〜翌0時）は当日の `allDay` にだけ入り、翌日に入らない。
  - 2日にまたがる予定（1日目 22:00〜2日目 02:00）は両日に入る。3日間の終日予定は3日すべてに入る。
  - 範囲外（8日後）の予定はどこにも入らない。
  - `timed` は開始時刻順に並ぶ。入力配列を変更しない。

### Task 5: 電源管理（判定・中継への指示・中継側）

**Files:** Create `src/core/power.js`, `src/services/plug.js` / Modify `relay/Code.gs` / Test `tests/power.test.js`, `tests/plug.test.js`, `tests/relay.test.js`

**Interfaces:**
- Produces（アプリ側）:
  - `plugDecision({ level, charging, low, high, last, nowMs }) -> 'on' | 'off' | null`
    - `level`: 0〜100 の数、または `null`（不明）。`charging`: 真偽値または `null`。`last`: `{ state: 'on'|'off', atMs } | null`（最後に**成功した**指示）

    - `level <= low`: `last` が `on` でなければ `'on'`。`last` が `on` でも `charging === false` で指示から5分以上たっていれば `'on'`（効いていないので再送）。
    - `level >= high`: `last` が `off` でなければ `'off'`。`last` が `off` でも `charging === true` で指示から5分以上たっていれば `'off'`。
    - その間（`low < level < high`）は `null`。
  - `relayUrlFor(relayUrl, params) -> string`（既存の `?token=…` を保ったままクエリを足す）
  - `sendPlug(settings, state, fetchFn) -> Promise<boolean>`（`action=plug&state=on|off`。応答が `{ ok: true, state }` で `state` が一致したときだけ true。それ以外、例外、配列の応答は false）
  - `sendHeartbeat(settings, fetchFn) -> Promise<boolean>`（`action=heartbeat`。`{ ok: true }` のときだけ true）
  - `loadPowerState(storage) / savePowerState(storage, last)`（キー `desk.power`）
- Produces（中継側 `relay/Code.gs`）:
  - `doGet(e)`: トークン検証は v1 のまま。`action` なし → 予定（今日0時 JST から7日間）。`action=plug` → `state` が `on`/`off` 以外は `{error:'bad_request'}`、SwitchBot の設定がなければ `{error:'plug_not_configured'}`、成功で `{ok:true,state}`、SwitchBot がエラーなら `{error:'plug_failed'}`。`action=heartbeat` → `{ok:true}`。`plug` と `heartbeat` はスクリプトプロパティ `LAST_SEEN` に現在時刻（ミリ秒）を書く。
  - `failSafe()`（時間主導トリガーから15分ごとに呼ぶ）: SwitchBot の設定があり、`shouldFailSafe(LAST_SEEN, now)` が true なら `turnOn` を送る。
  - `shouldFailSafe(lastSeenMs, nowMs) -> boolean`（`lastSeenMs` が数値でない、または `nowMs - lastSeenMs > 30分` で true）
  - `switchBotHeaders_(token, secret, t, nonce) -> { Authorization, sign, t, nonce, 'Content-Type' }`（`sign` は `token + t + nonce` を `secret` で HMAC-SHA256 し Base64 にしたもの）
  - `weekWindow_(now) -> { start: Date, end: Date }`
  - スクリプトプロパティ: `TOKEN`（v1）、`SWITCHBOT_TOKEN`, `SWITCHBOT_SECRET`, `SWITCHBOT_DEVICE_ID`, `LAST_SEEN`
  - SwitchBot への送信: `POST https://api.switch-bot.com/v1.1/devices/{deviceId}/commands`、本文 `{"command":"turnOn"|"turnOff","parameter":"default","commandType":"command"}`。応答の `statusCode === 100` を成功とする。
